# Как внести вклад

Pixel Editor это **активно развивающийся проект с открытым кодом**, и **пул-реквесты приветствуются**: исправления ошибок, новые операции, инструменты, переводы, документация, примеры.
English version: [../../CONTRIBUTING.md](../../CONTRIBUTING.md).

## С чего начать

- Идеи и известные пробелы: [IMPROVEMENTS.md](IMPROVEMENTS.md), [TOOLS_REVIEW.md](TOOLS_REVIEW.md) и [RELEASE.md](RELEASE.md) (чего ещё не хватает для релиза).
- Проще всего начать с небольших самостоятельных задач: новая операция, окно горячих клавиш, недавние цвета, отмена для свойств слоя, файл нового языка.
- Не уверены, подходит ли идея? Сначала откройте issue и опишите сценарий использования.

## Как отправить пул-реквест

1. Сделайте форк, создайте ветку от `main` (одна тема на ветку).
2. Соберите проект и прогоните тесты (Windows, .NET 10 SDK). `build.cmd --test` делает свежую сборку и гоняет оба проекта тестов; команды ниже это ручной способ:

   ```
   dotnet build
   dotnet test tests/PixelEditor.Tests
   dotnet test tests/PixelEditor.ViewModels.Tests
   dotnet run --project tests/PixelEditor.GuiSmoke     # открывает окно, нужен рабочий стол
   ```

3. Внесите изменение по правилам ниже, добавьте тесты, отправьте ветку и откройте пул-реквест. Опишите **что** изменено, **зачем** и как проверено (для видимых изменений приложите скриншоты).

## Правила проекта

- **Логика живёт в `PixelEditor.Core` и моделях представления**, а не в code-behind. Карта и правила для GUI в [AGENTS.md](docs/ru/AGENTS.md); прочитайте раздел, который затрагиваете.
- **Тесты:** каждое изменение поведения требует теста. Новая операция ещё и пример в `OperationsCatalogTests.Samples()`: тест запускает каждую операцию на настоящей картинке.
- **Тексты:** строки интерфейса идут через ключи локализации в **обоих** файлах `ru.json` и `en.json` (`{loc:T key}` в XAML, `Loc.T` в моделях). Тексты ядра, CLI и MCP через `CoreText.T/F` с английским переводом в `core.en.json`.
  Сообщения журнала **только английские** (`Log.Error(...)`); ошибки показывайте через `dialogs.ShowError(ex)`, чтобы они попадали в журнал.
- **Документация:** видимые пользователю изменения обновляют документы на двух языках (английские в корне и `docs/`, русские в `docs/ru/`; руководство для ИИ `docs/AI-GUIDE.md` только английское). Новые команды CLI и MCP-инструменты добавляйте в руководство для ИИ.
- **Доступ ИИ:** после добавления операции, команды или инструмента запустите `python scripts/audit_ai_access.py`; он должен закончиться сообщением, что всё доступно.
- **Стиль:** следуйте окружающему коду; цвета только токенами темы; новые зависимости только после обсуждения.
- **Файлы:** каждый новый `.cs` начинается с двух строк заголовка

  ```csharp
  // SPDX-License-Identifier: GPL-3.0-or-later
  // Copyright (C) 2026 mrl4an
  ```

  (в правимых файлах оставляйте исходный заголовок; за существенную работу можно добавить свою строку авторства).

## Лицензия вклада

Проект распространяется по **GPL-3.0-or-later** (см. [LICENSE](../../LICENSE)). Отправляя пул-реквест, вы соглашаетесь, что ваш вклад выпускается под той же лицензией
и что вы вправе его передать (не копируйте код и материалы с несовместимой лицензией; примеры картинок только CC0 или общественное достояние с записанным источником).

## Сообщения об ошибках

Откройте issue и укажите: версию (**Справка → О программе** или `pixed --version`), что вы делали, что ожидали и что получилось.
Приложите нужные строки журнала ошибок (**Справка → Открыть папку журнала ошибок**; записи английские и со стеком). В журнале есть пути к файлам: уберите личные.

## Вежливость

Будьте уважительны и конструктивны в issue и ревью. Мейнтейнеры могут попросить доработать или отклонить пул-реквест, не подходящий целям проекта: лёгкий, удобный пиксель-арт с бинарной прозрачностью и сильной автоматизацией для ИИ.
