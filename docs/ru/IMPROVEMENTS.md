# Список улучшений: новое, упрощение, сокращение

Состояние на момент составления: инструменты для ИИ (CLI, MCP, DLL), редактор с рисованием, выделением, слоями, палитрами, шаблонами, RSI и экспортом анимации.
Оценки: **польза** (В высокая, С средняя, Н низкая), **цена** (М малая до 1 дня, С средняя 2-4 дня, Б большая неделя и больше).

## 1. Для агентов (CLI, MCP, документация)

| № | Что | Польза | Цена | Зачем |
|---|---|---|---|---|
| A1 ✅ | **Компактные каталоги**: `pixed ops --names`, `pixed ops <имя>`, `palettes --names` (без списка цветов) | В | М | `pixed ops` это 7700 знаков (около 3-4 тыс. токенов) на каждый запрос, палитры 3000 знаков |
| A2 | **JSON из stdin и из файла с `@`**: `pixed run - in out < pipeline.json`, `draw @scene.json` | В | М | в PowerShell и cmd кавычки внутри JSON портятся: главная ловушка для агентов на Windows |
| A3 | **Шаблоны путей** (`slices\*.png`) в `sheet`, `gif`, `batch` | С | М | агент пробует маски, получает ошибку «синтаксическая ошибка в имени файла» |
| A4 | **Единые сообщения об ошибках на русском** (сейчас «Could not find file» от .NET) и подсказка «что делать» | С | М | меньше лишних шагов; можно добавить поле `Hint` в JSON ошибки |
| A5 | **`pixed doctor`**: версия, путь к инструментам, проверка .NET, WPF, прав записи, папки данных | В | М | убирает класс проблем «exe не найден», «нет PresentationCore», «нет прав» |
| A6 | **Команды сохранения в библиотеку**: `pixed save-template <имя> <json>`, `save-palette`, `validate <шаблон>` | С | М | в CLI сохранить шаблон можно только руками в AppData |
| A7 | **Проверка «похоже на исходник»** (`similarTo`: гистограмма или SSIM) и команда `pixed compare a.png b.png` | С | С | агент сможет доказать, что обработка не испортила картинку, не глядя на неё |
| A8 | **Текстовый предпросмотр**: `pixed ascii <img>` (символ на цвет + легенда) | С | М | для мелких спрайтов дешевле картинки и работает без картиночного канала |
| A9 | **Команды RSI**: `pixed rsi new/state/info/export` | С | С | сейчас RSI создаётся только в редакторе |
| A10 | **Сцена 2.0**: части с `offset` и `repeat`, ссылки на именованные части (`"use":"arm"`), `gradient`, `text` | С | С | персонажи и тайлы описываются ещё короче; меньше токенов на симметрию и повторы |
| A11 | **Пакет «одним файлом»**: `dotnet publish` с `PublishSingleFile` и готовый zip (exe, dll, AI-GUIDE.md) | В | М | агенту и пользователю не нужна сборка из исходников |
| A14 | Режим чата без агентов: скопировать запрос, вставить JSON-ответ, предпросмотр и применить; `chat-prompt`, `pipeline-check` | В | С | **сделано** |
| A12 | **Пакетная сцена**: `pixed draw-many <папка_json> <папка_png>` | Н | М | серия плейсхолдеров за один вызов |

Исправлено при перепроверке `AI-GUIDE.md` (см. раздел 4): пути Debug и Release, требование `UseWPF` для DLL, неполный рецепт «фото на текстурном фоне», нет пути сохранения шаблонов из CLI, битые ссылки на `AGENTS.md`, нет предупреждения о масках `*` и о размере каталогов.

## 3. Упростить и сократить

Цель: меньше кнопок и окон, больше очевидного. Это изменения интерфейса, а не удаление возможностей.

| № | Что сделать | Результат |
|---|---|---|
| S1 ✅ | **Сгруппировать инструменты:** Выделение (рамка, палочка, лассо, по точкам) в одну кнопку с вариантами, Фигуры (линия, прямоугольник, эллипс) в одну | в левой панели 15 кнопок станет около 9 |
| S2 | **Объединить «Переместить» и «Выделение»** в один инструмент «Двигать» (тянет выделение, а без него предмет) | убирается путаница после автопереключения |
| S3 | **Шаблоны: 11 стандартных свести к 6-7** («Фото в спрайт 32» и «Уменьшить до 64» перекрываются с «Картинка из интернета») | список короче, понятнее, меньше тестов |
| S4 | **Импорт: три пресета вместо россыпи опций** («Как есть», «Пиксель-арт», «Фото»); остальное в «Дополнительно» | диалог читается с первого взгляда |
| S5 | **Меню «Операции»:** оставить 6-8 частых пунктов, остальные операции только через шаблоны и конструктор | меню не пугает |
| S6 | **Убрать дублирование кнопок палитры** (панель и меню «Палитра»): панель только «Библиотека…», «+ В палитру», «− Убрать» | меньше мест, где одно и то же |
| S7 | **«Применять ко всем слоям»**: убрать переключатель из меню в диалог предпросмотра результата | реже нажимают случайно |
| S8 | **Текст и «Светлее / темнее»** оставить, но убрать с главной панели в группу «Ещё» | основная панель короче |
| S9 | **Слои по умолчанию:** режим «новый слой для фигур, вставки, текста» оставить, но добавить кнопку «Слить в один» и подсказку при первом включении | видно, откуда берутся слои |
| S10 | **Стандартные палитры:** оставить 6, свои с мусорными названиями чистятся вручную; добавить «Переименовать» в панели | порядок в библиотеке |

## 4. Найденные ошибки в `AI-GUIDE.md` при перепроверке (исправлены)

| Что было | Что сделано |
|---|---|
| Путь `bin\Debug`, а сборка `-c Release`: агент не находил exe | единый путь `<папка>`, сборка `dotnet publish -o <папка>` |
| Пример DLL не запускался без `UseWPF` (`PresentationCore`) | добавлен `.csproj` и пояснение, что для Core без файлов WPF не нужен |
| Рецепт «фото на текстурном фоне» отсылал к «шаблону без cutout», которого нет | добавлен готовый `photo.json` с `polygonMask`, проверен запуском |
| Сохранить шаблон можно было только через MCP | описан путь `%AppData%\PixelEditor\pipelines` для CLI (проверено) |
| Ссылки на `../AGENTS.md` ломались в копии вне репозитория | документ самодостаточен |
| Не было предупреждений: маски `*`, размер каталогов, вид ошибок в PowerShell | добавлены |
| Лимит «картинки до 8192» звучал как общий | уточнён: только `resize` и `resizeCanvas`; сцена до 512 |

Проверено запуском: коды выхода 0/1/2, `run` и `check` по имени шаблона, `draw` (пример из документа), `apply` с массивами и цветами, `batch`, `slice`, `sheet`, `gif` (оба вида), `anim-export`, список MCP-инструментов совпал с документом (21 из 21), имена шаблонов и операций совпали.

## 5. Замечания по состоянию данных

- В пользовательской библиотеке палитр лежит палитра с названием «ццццццццНовая палитра» (остаток ручных проб). Её можно удалить в окне «Библиотека палитр».
- `AGENTS.md` вырос до ~280 строк: стоит разбить по областям (карта, GUI, ядро, RSI), чтобы разработчику не читать всё сразу.
